# 01 · Background & Goals

> [Home](../README.en.md) ｜ [中文](01-背景与目标.md)

## Pain points

Before delivery (exams, publishing, item-bank ingestion) papers need human review. The traditional approach struggles with:

- **Volume**: dozens to hundreds of questions per paper, dozens of papers per batch — too much to read word by word.
- **Inconsistent standards**: reviewers disagree on "is this an error" and "how severe is it".
- **Misses**: typos, punctuation and missing options are tractable; but **whether figures match the text** (a label in the figure differs from the stem) and **whether a question collides with a historical one** are nearly impossible to catch fully by eye.
- **Multiple languages**: zh/ja/de/fr papers each have their own spelling, grammar and punctuation rules that a reviewer may not fully master.

## Goals

Turn review into a **routable, reviewable, measurable** pipeline platform:

1. **Auto-split questions**: split a whole document into a structured per-question list (major/minor numbering & hierarchy, stem, options, answer, reference material).
2. **Per-question routing**: first decide "which kinds of problems to check" for each question, avoiding wasted detections on inapplicable ones.
3. **Multi-class detection**: typos, semantics, options, punctuation, type mismatch, missing info, unsolvable, answer leakage, **image-text consistency**, etc., across languages.
4. **Dedup & aggregate**: merge duplicate reports from multiple tasks at the same location / same root cause into one clean list.
5. **Plagiarism**: intra-paper, cross-paper (same batch & subject), and against historical papers.
6. **Evaluation**: quantify detection ability with a labeled dataset (precision/recall/F1/F2).
7. **Review & accumulation**: humans confirm/reject/annotate each issue, and can distill typical judgments into a case library (dynamic few-shot).
8. **Reports**: Word review report, Excel issue detail, detection-process detail, full-batch ZIP.

## Target users

- **Teaching-research / review staff**: pre-screen large volumes of papers, reducing manual first-pass work.
- **Publishing / item-bank ops**: batch QA, historical dedup, version regression.
- **Model / data teams**: use the evaluation line to quantify detection effect before/after "swapping the model / adding a case library".

## Why "the hard part is the figures"

Text-class errors (typos, punctuation) are relatively mature; the truly hard and valuable part is **image-text consistency**: a figure-bearing question whose stem says "the angle in the figure is 30°" while the figure shows 45°, or that simply pairs the wrong figure. Multimodal models are prone to "describing the figure fluently while missing the key anchor" on this fine-grained reconciliation. This project designs a four-stage multimodal pipeline for exactly this (see [07](07-图片审校深挖.en.md)), and the resulting capability was distilled into a standalone image-text consistency benchmark, [EduFig-IC](https://github.com/CODE-BULIAO/edufig-ic).

## Final deliverables

| Deliverable | Purpose |
|------|------|
| Per-question issue list | Item-by-item human review (question no., type, severity, description, fix suggestion, source anchor) |
| Word review report | For teaching-research/review/external collaborators to read & circulate |
| Excel issue detail | Filtering, statistics, further processing |
| Detection-process detail Excel | Inspect each detection's input/output/latency/whether the case library was hit |
| Excel evaluation report | precision/recall/F1/F2/FPR and other effect metrics |
| Batch ZIP | One-shot download of a whole batch's results |
