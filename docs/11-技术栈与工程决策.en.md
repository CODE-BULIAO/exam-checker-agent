## Tech stack

### Backend

| Category | Choice | Use |
|---|---|---|
| Language | Python 3.12 | All backend |
| Primary web framework | FastAPI | Business API, routing, DI |
| Legacy web framework | Flask + Werkzeug | Legacy detection/parse API, called via in-process bridge |
| ASGI | Uvicorn | Process entry (`backend.main:app`) |
| Validation | Pydantic 2 | Request/response models |
| Database | SQLite (stdlib) | Single-file storage, schema in `core/database.py` |
| LLM client | openai SDK | OpenAI-compatible protocol (cloud + local vLLM) |
| LLM orchestration | langchain 0.3.x | Parts of the detection chain (e.g. the image chain) |
| Document parsing | python-docx / PyMuPDF / pdfplumber | DOCX/PDF parsing, SVG→PNG |
| Reports | python-docx / openpyxl / lxml | Word/Excel reports |
| Imaging | Pillow | Scaling, min-size upscale |
| Vectors | sentence-transformers / numpy | Plagiarism + dynamic few-shot recall |
| Text matching | thefuzz / python-Levenshtein / json-repair | Section location, LLM JSON repair |
| Language detection | langid | zh/en discrimination |
| Config | PyYAML | `llm_config.yaml` / `app.yaml` |

### Frontend

React 19 · TypeScript · Vite · Tailwind CSS. In dev, Vite proxies `/api`, `/health` to 8777; in prod, the built `frontend/dist` is statically served by the backend.

### Infrastructure

Docker two-layer image (a dependency base layer + an app layer) · `deploy.sh` one-command build & run · data dir `DATA_DIR` (`app.db` + `uploads/` + `batches/`) · pytest (`backend/tests/`, run from the repo root).

## Config system

- **Deploy mode** `cloud / private / test` (env `SMART_CHECKER_DEPLOY_MODE` > `app.yaml` > default), flipping feature flags per mode.
- **LLM catalogue** in `llm_config.yaml` (base_url / api_key / model lists / display names); priority **env > yaml > code default**. Local vLLM overridden via `LOCAL_LLM_HOST`.
- **Long/short budget split** `LLM_SHORT_MAX_TOKENS` / `LLM_LONG_MAX_TOKENS` (see [10](10-量化指标与评测.en.md)).
- **Runtime-level overrides**: temporarily override feature flags per request (e.g. an extraction-thinking switch).

## Key engineering decisions & trade-offs

| Decision | Choice | Trade-off |
|---|---|---|
| How to attach legacy detection | FastAPI + in-process Flask WSGI bridge | ✅ Zero network hop reuse, smooth migration ❌ Dual stack is transitional; middleware doesn't auto-cover Flask |
| Detection scheduling | Question-level concurrency + no per-question multi-task concurrency + group by task | ✅ Aligns with frontend concurrency, helps vLLM prefix cache, reduces prompt mixing ❌ Sacrifices intra-question parallelism |
| Dedup | Deterministic priority layer primary + LLM aggregation secondary | ✅ Trunk reproducible/testable/auditable ❌ Rules need maintenance |
| Image detection | Four-stage + text-only re-review | ✅ Recall up a lot while keeping precision ❌ More tokens & latency, longer prompts |
| Image re-review direction | false→true only | ✅ Hard guard on precision ❌ Can't fix Step 3 over-reports |
| LLM output | Unified JSON template across tasks + locked error_type | ✅ Stable parsing, regressable ❌ Verbose to write the constraints |
| Storage | SQLite + local files | ✅ Single file, easy deploy, zero ops ❌ Horizontal scaling needs rework |
| Identity | localStorage UUID + X-Client-Id ownership isolation | ✅ Enough for an internal tool; cross-owner returns 404 to avoid leakage ❌ Not auth, forgeable |

## Robustness & security boundaries

- **Idempotent migrations**: table creation + `ALTER TABLE ADD COLUMN` centralized in one file; old DBs auto-upgrade on startup; read old DBs defensively with `row["col"] if "col" in row.keys()`.
- **Parse fault tolerance**: concurrent fill falls back to serial on failure; JSON fixed with `json_repair`; degenerate-repetition detection as a backstop.
- **Task self-healing**: heartbeat + startup recovery (see [09](09-重试与韧性.en.md)).
- **Ownership isolation**: cross-owner always 404; but this is session-level isolation, not authentication.
- **Aggregation never drops errors**: LLM aggregation failures fall back to keeping the originals.

## Evolution directions

- Extract `smart_checker` into a standalone process/microservice, replacing the in-process bridge with HTTP/gRPC (the dual stack is transitional).
- Upgrade the batch engine from a thread pool to a distributed queue (Celery / RQ / Arq).
- Upgrade identity to real OIDC/JWT auth, `owner_id` → user id + audit.
- SQLite → Postgres (the idempotent `ALTER` migrations are already in place).
- Make the detection pipeline more agentic: self-feedback after routing, tool-using adjudication in aggregation, budget-aware scheduling (see [05](05-路由与Agent还是工作流.en.md)).
