### 前端

React 19 · TypeScript · Vite · Tailwind CSS。开发态 Vite 代理 `/api`、`/health` 到 8777；生产态构建 `frontend/dist` 由后端静态托管。

### 基础设施

Docker 两层镜像（依赖 base 层 + 应用层）· `deploy.sh` 一键构建启动 · 数据目录 `DATA_DIR`（`app.db` + `uploads/` + `batches/`）· pytest（`backend/tests/`，根目录运行）。

## 配置体系

- **部署模式** `cloud / private / test`（`SMART_CHECKER_DEPLOY_MODE` 环境变量 > `app.yaml` > 默认），按模式翻转 feature flags。
- **LLM catalogue** 在 `llm_config.yaml`（base_url / api_key / 模型列表 / 显示名），优先级 **环境变量 > yaml > 代码默认**。本地 vLLM 用 `LOCAL_LLM_HOST` 覆盖。
- **长/短预算拆分** `LLM_SHORT_MAX_TOKENS` / `LLM_LONG_MAX_TOKENS`（见 [10](10-量化指标与评测.md)）。
- **Runtime 级覆盖**：支持按请求临时覆盖 feature flag（如抽取 thinking 开关）。

## 关键工程决策与权衡

| 决策 | 选择 | 权衡 |
|---|---|---|
| 旧检测能力怎么接 | FastAPI + 进程内 Flask WSGI 桥接 | ✅ 零网络跳跃复用旧逻辑、平滑迁移 ❌ 双栈是中间态，中间件不自动覆盖 Flask |
| 检测调度 | 题目级并发 + 单题不并发多任务 + 按 task 分组 | ✅ 对齐前端并发、利好 vLLM prefix cache、减少 prompt 混跑 ❌ 牺牲单题内并行 |
| 去重 | 确定性优先级层为主 + LLM 聚合层为辅 | ✅ 主干可复现可测可审计 ❌ 规则需要维护 |
| 图文检测 | 四段式 + 纯文本复审 | ✅ 召回大幅提升且保精确率 ❌ token 与延迟增加、Prompt 更长 |
| 图文复审方向 | 只许 false→true | ✅ 硬保护精确率 ❌ 无法纠正 Step3 的过报 |
| LLM 输出 | 全任务统一 JSON 模板 + 锁死 error_type | ✅ 解析稳、可回归 ❌ Prompt 约束写起来啰嗦 |
| 存储 | SQLite + 本地文件 | ✅ 单文件好部署、零运维 ❌ 水平扩展需改造 |
| 身份 | localStorage UUID + X-Client-Id 归属隔离 | ✅ 内部工具够用、跨 owner 返回 404 防泄露 ❌ 非认证、可伪造 |

## 健壮性与安全边界

- **幂等迁移**：建表 + `ALTER TABLE ADD COLUMN` 集中在一个文件，老库启动自动升级；读旧库用防御式 `row["col"] if "col" in row.keys()`。
- **解析容错**：并发填充失败回退串行；JSON 用 `json_repair` 修复；退化重复检测兜底。
- **任务自愈**：心跳 + 启动回收（见 [09](09-重试与韧性.md)）。
- **归属隔离**：跨 owner 一律 404；但这是会话级隔离，不是认证。
- **聚合不丢错**：LLM 聚合失败回退保留原错误。

## 演进方向

- 把 `smart_checker` 抽成独立进程/微服务，用 HTTP/gRPC 替换进程内桥接（双栈是中间态）。
- 跑批引擎从线程池升级为分布式队列（Celery / RQ / Arq）。
- 身份升级为真正的 OIDC/JWT 认证，`owner_id` → 用户 ID + 审计。
- SQLite → Postgres（幂等 `ALTER` 迁移已就位）。
- 检测链路更 agentic：路由后自反馈、聚合带工具裁决、预算感知调度（见 [05](05-路由与Agent还是工作流.md)）。
